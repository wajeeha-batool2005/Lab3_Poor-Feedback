# Lab 03 - Poor Feedback Design

## Overview
This project demonstrates a **poor feedback design** scenario in Human-Computer Interaction (HCI). It consists of a simple web page with a **button** that processes an action and provides minimal feedback to the user. The aim is to highlight how inadequate or delayed feedback can affect user experience.

---

## Features
- Interactive button labeled **"Process Data"**.
- Click counter to track the number of times the action has been performed.
- Visual feedback through button animation and status messages:
  - ✅ Shows "Processed X time(s)" for valid actions.
  - ⚠️ Shows "Limit reached!" when maximum allowed clicks are exceeded.
- Button disables after exceeding the action limit, demonstrating poor feedback for blocked actions.

---

## How to Run
1. Clone or download the repository.
2. Open `lab3.html` or `index.html` in a web browser.
3. Click the **Process Data** button to observe the behavior.

---

## Technology Stack
- HTML
- CSS
- JavaScript (vanilla JS)

---

## Notes on Poor Feedback Design
- The button only slightly animates when clicked, providing minimal visual feedback.
- Status messages appear, but users may not immediately notice the limit reached warning.
- This lab demonstrates the importance of **clear, timely, and perceivable feedback** in interface design.
